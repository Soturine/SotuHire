# Migração v1.10.1

Origem esperada: schema 6. Destino: schema 7.

O runner cria backup antes da aplicação, registra history/metadata e aplica DDL idempotente. Tabelas novas não transformam dados pessoais nem copiam stores JSON automaticamente.

Fluxo recomendado:

```bash
python scripts/migrate_storage.py --dry-run
python scripts/migrate_storage.py --apply
python scripts/check_data_health.py
```

Novas tabelas: opportunity observations/rankings, taxonomy datasets/mappings, interview sessions/preparations/questions/answers, STAR, follow-up, tasks, reminders e plans. Reexecutar `ensure_database` não altera entidades existentes.

Rollback operacional: restaurar o backup criado antes da migration. Não reduzir manualmente `schema_version`.
