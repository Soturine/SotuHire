# Auditoria de dead code, dedupe e arquitetura — v2.0

O inventário classificou rotas e módulos em ACTIVE, PUBLIC_API, INTERNAL, DYNAMIC_ENTRYPOINT,
COMPATIBILITY, LEGACY_ACTIVE, DEV_TOOL, TEST_ONLY, RELEASE_ONLY e HISTORICAL. Nenhum item foi
removido apenas por ausência de referência estática: TanStack routes, prompts e CLI são dinâmicos.

Os três arquivos authenticated-browser são PUBLIC_API/NO_TOUCH. JSON/JSONL é LEGACY_ACTIVE ou
COMPATIBILITY; não foi apagado. O novo domínio v2 elimina dual-write: SQLite é o único writer.
Duplicação evitada: uma repository para graph/portfolio/proposals; uma approval boundary; um tool
registry; um v2 API client no frontend. Não houve DEAD comprovado seguro para remoção neste batch.
