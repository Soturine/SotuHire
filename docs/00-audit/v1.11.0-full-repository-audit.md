# Auditoria integral do repositório — v1.11.0

## Escopo e método

Foram auditados Python/API, web, Companion/extensão, workflows, scripts, dependências, persistência,
AI task registry, documentação e assets. Busca dirigida cobriu stores, writers, consumers, flags,
aliases legados, endpoints sem client, client sem endpoint e referências de versão.

## Classificação

| Área | Classe | Evidência/decisão |
| --- | --- | --- |
| API e web ativos | ACTIVE | rotas registradas, clients e testes dirigidos |
| scripts de release/captura | RELEASE_ONLY | consumidos manualmente/CI; manter |
| prompts e schemas registrados | ACTIVE | 25/25 tasks têm prompt, schema, purpose, scope e consumer |
| adapters/aliases antigos | COMPATIBILITY | preservam dados/clients antigos; não remover nesta release |
| fixtures e mocks | TEST_ONLY/DEV_TOOL | demo é identificada e não escreve API Real |
| stores JSON/JSONL operacionais | LEGACY_ACTIVE | health, backup e migração explícita para SQLite já existem |
| export/config/cache/taxonomy JSON | ACTIVE | formato apropriado, não aggregate relacional concorrente |
| scripts históricos versionados | RELEASE_ONLY | reproduzem releases antigas; fora da jornada atual |

Nenhum arquivo foi removido como DEAD sem prova de ausência de import, entrypoint dinâmico,
compatibilidade, teste ou uso de release. Duplicação de URL/path sanitization foi reduzida aos
boundaries centrais; adapters de compatibilidade permanecem intencionais.

## Stores legados

`legacy_migration.py` já cobre profile, career memory, tracker, opportunities, sources, public
exams, Radar, schedules, Companion e portfolio, com backup, idempotency/history e preservação das
fontes. Writers continuam necessários para clients legados e rollback. Não houve schema 8 nem
dual-write novo: analytics é derivado do SQLite e taxonomy/config/cache são snapshots/configuração.

## Limitações honestas

- migração de store é explícita; arquivos legados não são apagados automaticamente;
- conectores autenticados protegidos não foram alterados;
- qualidade de modelos locais depende de benchmark por modelo e permanece `unverified` até isso;
- internacionalização do shell, metadata, ajuda, onboarding e preferências está catalogada; telas
  históricas ainda possuem conteúdo PT-BR a ser migrado incrementalmente, sem falsa alegação de
  cobertura total.
